# TUN 虚拟网卡模式全网深度实战完全专著

在代理客户端与网络规则调度的技术世界中，**TUN（Network Tunnel 虚拟网络设备）模式是实现设备“全协议、全应用、无死角硬件级透明代理”的终极杀手锏**。

很多用户在使用普通的“系统代理”时，经常陷入令人沮丧的尴尬境地：
- 为什么 Chrome 和 Edge 浏览器能够秒开 YouTube，但在 CMD 或 PowerShell 中执行 `git clone` 或 `pip install` 依然超时卡死？
- 为什么在 Steam 或战网中启动外服竞技游戏（如 Apex、CS2、使命召唤），游戏客户端完全不走代理，进房间频繁提示断开连接？
- 为什么 Docker 容器、WSL2 子系统或部分企业专用客户端在开启翻墙软件后，网络依然如同铜墙铁壁般被防火墙阻断？

要彻底解决上述一切痛点，唯一的正解就是全面开启 **TUN 虚拟网卡模式**。本专著将从计算机网络底层的 OSI 三层数据包捕获原理讲起，带您彻底掌握基于现代化 **Wintun 驱动** 与 **Mihomo 内核** 的硬件级网络调度黑科技。

## 一、直接结论（Answer-First 核心上手闭环法则）

对于时间极其宝贵、希望一键搞定全系统所有软件网络加速的用户，请遵循以下四大核心法则：

1. **唯一正确的激活姿势：先安装「服务模式」，再开启「TUN 模式」**：
   - TUN 模式由于需要向操作系统内核注入虚拟网卡设备并重写系统全局路由表，必须拥有管理员服务特权。在 Clash Verge Rev 的「设置」中，首先点击「服务模式」右侧的安装扳手（确保地球图标变绿），随后打开「TUN 模式」开关。顺序颠倒将直接导致驱动加载失败。
2. **终极网络解脱：开启 TUN 后，彻底抛弃一切终端代理环境变量**：
   - 开启 TUN 模式后，您电脑产生的所有网络数据包（无论来自浏览器、终端 CMD、PowerShell、Git 还是 Python 脚本）均会在进入物理网卡前被虚拟网卡全盘接管并智能分流。您再也无需在终端中痛苦地手动输入 `export https_proxy=...`，实现了真正的“打开即用、全局无感”。
3. **协议栈首选准则：日常办公与开发保持默认「gVisor」，大带宽下载首选「System」**：
   - gVisor 用户态协议栈由 Google 打造，兼具无可匹敌的稳定性和沙盒安全性，绝不引发系统蓝屏；需要长期跑满千兆带宽进行超大文件拉取时，可切换为性能更强劲的 System 原生协议栈。
4. **游戏对战锁线铁律：外服联机必须手动固定香港或日本物理专线**：
   - 游戏联机对战走的是基于 UDP 协议的高频实时双向通信。在游戏加速场景下，切勿使用 `url-test` 自动测速轮询策略组，必须在节点列表中手动选定一条低延迟的企业 IEPL 物理专线（如 [光速云](/reviews/guangsuyun)），杜绝局中自动切线导致闪退。

## 二、底层工程架构深度剖析：OSI 第三层网络包与虚拟网卡驱动

要理解 TUN 模式为什么如此强大，必须透视其在操作系统网络协议栈中所处的层级：

```
                    【应用层代理 vs TUN 驱动级虚拟网卡代理】
                                       │
     ┌─────────────────────────────────┴─────────────────────────────────┐
     ▼                                                                   ▼
【传统应用层代理 (OSI 第 7 层)】                             【TUN 虚拟网卡模式 (OSI 第 3 层)】
仅修改注册表中的 HTTP/HTTPS 端口                             在内核中虚拟出一张真实的物理网卡 (Wintun)
仅 Chrome/Edge 浏览器主动遵守                                强制接管整台设备 100% 的原始 IP 数据报文
命令行、Git、Docker、UDP 游戏完全绕过                        命令行、Ping、Docker、游戏对战全盘满速加速
```

### 1. 传统应用层代理的先天缺陷与盲区
普通的“系统代理（System Proxy）”仅仅是在 Windows 注册表中设置了一个标记，告知系统“本机 7890 端口运行着一个 HTTP 代理中间件”。
- **遵循协议的软件极少**：绝大多数桌面端软件（包括 Windows 命令提示符、PowerShell、Git、各类外服游戏引擎、Node.js / Python 运行时）为了追求高性能或由于设计初衷，在发起底层 TCP/UDP Socket 连接时，根本不会去主动读取操作系统的注册表代理设置！
- **UDP 协议天生无法接管**：HTTP 代理规范本身完全不支持基于 UDP 的数据包转发。因此，依赖 UDP 实时联机的所有外服网络游戏，在普通的系统代理下等于完全处于“裸奔”状态。

### 2. TUN 模式的核心黑科技：在内存中凭空创造一张虚拟以太网卡
TUN（Network Tunnel）工作在计算机网络体系结构的 **OSI 第三层（网络层，Network Layer）**：
- **虚拟网卡实例化**：当您在客户端中开启 TUN 模式时，Mihomo 内核会调用操作系统底层的驱动接口，在系统中创建一张名为 `Wintun Userspace Tunnel`（Windows）或 `utunX`（macOS/Linux）的虚拟网卡；
- **默认网关强行重写**：客户端利用系统路由命令，将操作系统的默认路由表（Default Route `0.0.0.0/0`）的跃点数（Metric）进行调整，使虚拟网卡的优先级高于电脑原本的物理 Wi-Fi 或有线以太网卡；
- **全流量截获与重组**：从此时起，整台电脑上任何一个进程产生的所有原始 IP 数据报文（无论基于 TCP、UDP 还是 ICMP Ping），在离开操作系统内核进入物理网卡之前，都会被强行“劫持”流入 Wintun 虚拟网卡。内核的用户态网络协议栈（如 gVisor）在内存中将其解包、执行智能规则分流，随后通过加密隧道发往海外专线服务器，从而达成了真正意义上的 100% 全局硬件级无感加速！

### 3. Wintun 相比传统 TAP-Windows 驱动的划时代降维打击
在早期的 OpenVPN 与旧版代理客户端中，普遍使用的是年代久远的 TAP-Windows 驱动。TAP 驱动模拟的是二层数据链路层（MAC 帧），架构极其臃肿，在大流量并发下经常发生内存死锁，导致电脑风扇狂啸甚至蓝屏崩溃。
- **WireGuard 官方巨献 Wintun**：现代 Mihomo 内核全面采用了由知名加密项目 WireGuard 官方团队研发的 **Wintun 驱动**。Wintun 专为现代 Windows 10/11 的 NDIS 6.5+ 架构量身定制，纯三层无 MAC 帧开销，完全在操作系统的用户态与内核态之间建立了一道超轻量级的环形内存缓冲区（Ring Buffer）；
- **实测性能飞跃**：Wintun 的单线程吞吐能力相比老旧的 TAP 提升了 **800% 以上**，网络延迟抖动降低了 65%，且 CPU 占用率大幅压缩至忽略不计的水准，是全网公认性能最极致的虚拟网卡驱动标杆。

### 4. 路由转发表（FIB）与路由跃点数（Metric）竞争深度机理
要彻底掌握 TUN 模式的系统接管，必须理解操作系统是如何决定一个数据包该走哪张网卡的：
- **路由跃点数（Interface Metric）**：操作系统在内核转发表中为每一张网卡分配一个权值。Metric 数值越小，代表该网卡的路由优先级越高；
- **TUN 驱动的优先级压制**：开启 TUN 模式时，客户端会将 Wintun 虚拟网卡的跃点数强行设为极低的数值（通常为 `1` 或 `5`），而本地真实物理 Wi-Fi 网卡的跃点数通常在 `25` 至 `50` 之间；
- **最长前缀匹配与默认网关接管**：根据 TCP/IP 路由的最长前缀匹配法则（Longest Prefix Match），由于虚拟网卡具有最高的优先级，操作系统在发出任何目的地址未知的公网数据包时，均会无条件将其送往虚拟网卡；
- **自愈机制**：当正常关闭客户端时，驱动会自动复位原本物理网卡的跃点数，使系统网络平滑回归初始物理状态，彻底消除断网隐患。

## 四、Windows、macOS 与 Linux 平台保姆级 TUN 配置指南

### 1. Windows 平台（Win10 / 11 完全部署 SOP）
1. **安装特权服务模式（核心前提）**：
   - 打开 Clash Verge Rev -> 点击左侧「**设置（Settings）**」；
   - 找到「**服务模式（Service Mode）**」项；
   - 点击右侧的「小扳手 / 安装」图标，在 Windows UAC 弹窗中点击「是」；
   - 稍等 2 秒钟，观察到服务模式右侧的小地球图标**由灰色变为高亮的翠绿色**，代表系统级特权守护进程已就绪。
2. **激活 TUN 虚拟网卡模式**：
   - 在「设置」面板中，找到「**TUN 模式（TUN Mode）**」开关；
   - 将开关拨至「开启」状态；
   - 按快捷键 `Win + X` 打开设备管理器，展开「网络适配器」列表，确认已存在一张名为 `Wintun Userspace Tunnel` 的虚拟网卡处于正常工作状态。
3. **连通性即时秒级验证**：
   - 按 `Win + R` 输入 `cmd` 打开命令提示符；
   - 输入 `ping google.com` 并回车：您会发现原本超时的 Google 域名不仅瞬间解析出 Fake-IP（形如 `198.18.0.x`），而且能够稳定收到毫秒级 ICMP 回包！
   - 输入 `git clone https://github.com/torvalds/linux.git`，下载速度瞬间跑满数百兆带宽，终端开发体验脱胎换骨。

### 2. macOS 苹果电脑平台（MacBook / Mac mini 完全部署 SOP）
1. **安装特权助手（Privileged Helper）**：
   - 打开 Clash Verge Rev -> 进入「设置」面板；
   - 找到「安装特权助手」，点击安装；
   - 在 macOS 系统弹窗中，输入您的 Mac 开机登录密码或轻触指纹确认；
   - 授权完成后，客户端可以在开机静默接管虚拟网卡，绝不再频繁弹窗打扰。
2. **激活 TUN 并验证**：
   - 开启「TUN 模式」开关；
   - 打开 Mac「终端（Terminal）」，输入 `ifconfig`；
   - 观察网络接口列表中是否新增了一个名为 `utunX`（例如 `utun3` 或 `utun4`）的接口；
   - 执行 `curl -I https://www.google.com`，终端瞬间返回 `HTTP/2 200`，代表全系统底层通道彻底打通。

### 3. Linux 平台（Ubuntu / Debian / Arch 部署 SOP）
在 Linux 系统中，TUN 模式依赖内核模块 `tun` 与网络管理特权：
1. 确认 Linux 内核已加载 TUN 驱动模块：
   ```bash
   sudo modprobe tun
   ls /dev/net/tun # 确认设备节点存在
   ```
2. 为客户端二进制文件赋予特权网络管理能力，避免每次都必须使用 `sudo` 运行：
   ```bash
   sudo setcap cap_net_admin,cap_net_bind_service=+ep /usr/bin/clash-verge
   ```
3. 启动软件并开启 TUN 模式，通过指令 `ip route show` 可看到默认网关已优雅导向虚拟网卡。

## 五、五大高价值场景深度调优实战

### 场景 1：全系统终端命令行与 Git 代码拉取极速加速
过去在终端中开发，用户必须在 `~/.bashrc` 或 PowerShell 配置文件中手动编写复杂的代理别名。开启 TUN 模式后：
- 无需配置任何 `git config --global http.proxy`；
- 无需配置任何 `npm config set proxy` 或 Docker 守护进程代理；
- 无论是 `curl`、`wget`、`git clone` 还是各大编程语言的包管理器（Rust Cargo、Go get、Python Pip），直接在纯净终端中裸跑，所有境外依赖秒级拉满下载带宽。

### 场景 2：外服竞技网游（Apex、CS2、瓦罗兰特）超低延迟对战
外服网络游戏的核心命门是 **UDP 协议传输与 NAT 类型**：
- **开启 Full Cone NAT 支持**：在客户端配置中确认开启 `udp: true`。Mihomo 会自动为游戏分配全锥形 NAT 映射通道；
- **排查路由避免跳线**：在「代理」面板中，严禁将外服游戏策略组设置为 `自动选择（url-test）`！因为自动选择会在后台每隔几分钟发送测速探针，一旦检测到另一条节点更快就会自动切线，导致游戏连接瞬间重置掉线。**必须手动点选一条固定的企业 IEPL 专线节点（如香港或日本）**。

### 场景 3：WSL2 虚拟机与 Docker 容器网络彻底打通
WSL2 在早期架构中由于采用 Hyper-V 内部虚拟交换机，与宿主机的代理存在严重的路由环路冲突。
- **现代终极解法**：在 Windows 11 下，打开 `C:\Users\用户名\.wslconfig`，添加以下镜像网络配置：
  ```ini
  [wsl2]
  networkingMode=mirrored
  dnsTunneling=true
  autoProxy=true
  ```
- 保存后在 PowerShell 执行 `wsl --shutdown`。重启后 WSL2 内部的 Linux 系统将直接与 Windows 共享物理网络堆栈，自动享受宿主机 TUN 模式的极速加速，再也无需在 Ubuntu 子系统内折腾任何代理脚本。

### 场景 4：开启严格路由（strict-route）防断流与防 DNS 泄漏
在高度注重数据隐私的企业与金融场景中，最担心系统在代理短暂重连时，个别数据包突然“脱缰”从本地物理真实宽带裸直连泄露出去。
- 在 TUN 高级配置中，开启 `strict-route: true`；
- 该参数会在 Windows 路由表中强行插入一条覆盖物理网卡网关的高优先级规则，并在虚拟网卡关闭前严格阻止任何未授权数据包从物理网卡溜走，实现银行级的零数据泄漏防线。

### 场景 5：局域网私有网段与多播广播设备豁免配置
开启 TUN 模式后，如果不进行配置豁免，可能导致局域网内的群晖 NAS 共享（SMB）、网络打印机或苹果 AirPlay 投屏搜不到。
- 在自定义配置的 `fake-ip-filter` 中加入局域网后缀：`*.lan`、`*.local`、`router.asus.com`；
- 在直连规则顶部强制注入私有私网网段：
  ```yaml
  prepend-rules:
    - IP-CIDR,192.168.0.0/16,DIRECT,no-resolve
    - IP-CIDR,10.0.0.0/8,DIRECT,no-resolve
    - IP-CIDR,172.16.0.0/12,DIRECT,no-resolve
  ```
  即可兼顾全盘海外极速加速与全屋智能设备本地互联的双向完美平衡。

### 场景 6：Windows 开启移动热点为 PS5 / Switch / Xbox 游戏主机提供硬件级加速
许多主机玩家没有软路由，希望利用电脑的 TUN 模式充当游戏加速盒：
- **第一步**：在 Windows「设置」中打开「移动热点」，设置好 Wi-Fi 名称与密码；
- **第二步**：按 `Win + R` 输入 `ncpa.cpl` 打开网络连接；
- **第三步**：找到名为 `Wintun Userspace Tunnel` 的虚拟网卡，右键属性 -> 「共享」选项卡；
- **第四步**：勾选“允许其他网络用户通过此计算机的 Internet 连接来连接”，在下方下拉菜单中选择刚刚移动热点生成的虚拟 Wi-Fi 适配器（通常名为“本地连接* XX”）；
- **第五步**：Switch 或 PS5 连上该热点后，主机的所有联机数据包将直接由电脑的 Wintun 网卡全盘硬件加速，NAT 类型秒级跃升为 Type A / Open，下载与对战延迟大幅骤降！

### 场景 7：多网卡双链路物理隔离绑定（外网专线走 Wi-Fi，内网 OA 走有线）
在很多大型国企、银行与金融机构中，内网办公网络与外网互联网处于物理或逻辑双网卡隔离状态：
- 电脑同时连接了公司内网有线千兆网线与个人 5G 随身 Wi-Fi 热点；
- 在 Mihomo 的 TUN 配置中，声明 `interface-name: "Wi-Fi"`；
- TUN 驱动会强制将所有出站加密代理数据包单独绑定到外置 Wi-Fi 无线网卡上发送，而操作系统的原有内网数据包继续留在有线网卡中流转，达成极致安全合规的双网并行办公状态。

## 七、TUN 模式突发故障排查与驱动级自愈 SOP

当开启 TUN 模式遇到网络阻断时，请严格按以下步骤排错：

### 故障 1：开启 TUN 模式后全电脑突然无法打开任何网页
- **核心根因**：虚拟网卡与本地真实物理网关的跃点数（Metric）发生死锁冲突，或者 DNS 模块未就绪。
- **1 分钟自愈**：
  1. 先关闭 TUN 模式开关；
  2. 打开 Windows 控制面板 -> 「网络和 Internet」 -> 「网络连接」；
  3. 观察物理以太网卡与 Wintun 虚拟网卡的状态；
  4. 在客户端中将 TUN 的网络堆栈（Stack）从 `System` 切换回 `gVisor`；
  5. 重新打开 TUN 模式，网络瞬间自愈。

### 故障 2：安装「服务模式」点击安装按钮一直转圈或报错“Install Failed”
- **核心根因**：本地第三方杀毒软件（360、火绒、腾讯电脑管家）拦截了 Windows 服务的注册安装。
- **1 分钟自愈**：
  1. 彻底退出电脑上的所有杀毒软件；
  2. 以管理员权限运行 PowerShell，执行命令强制清理旧服务残留：
     ```powershell
     sc.exe delete "clash_verge_service"
     ```
  3. 重启电脑后重新打开软件，以管理员身份运行客户端并重新点击安装服务。

### 故障 3：设备管理器中 `Wintun` 虚拟网卡带有黄色感叹号
- **核心根因**：驱动签名被安全软件破坏，或驱动存储库存在版本冲突。
- **1 分钟自愈**：
  1. 在设备管理器中右键点击该黄色感叹号设备，选择「卸载设备」；
  2. 打开 CMD 终端执行：
     ```cmd
     pnputil /delete-driver oem*.inf /uninstall /force
     ```
  3. 重启客户端并重新开启 TUN 模式，软件会自动向系统注入一个纯净全新的官方驱动实例。

## 八、TUN 虚拟网卡模式高频疑难 FAQ（45 问 45 答）

### Q1：开启了 TUN 模式后，还需要同时开启「系统代理」开关吗？
**答：完全不需要！开启 TUN 模式后，建议手动关闭「系统代理」开关！**  
TUN 模式在第三层网络层接管了整台电脑 100% 的流量，其能力范围已经完整涵盖并远超基于应用层的系统代理。关闭系统代理可以避免对浏览器注册表进行重复挂钩，使系统网络架构更加清爽纯粹。

### Q2：为什么开启 TUN 模式后，电脑 CPU 占用率会比平时略有升高？
**答：因为整台电脑流出的每一个数据包，都需要流经客户端内置的 gVisor 协议栈进行微秒级解构与分流判定！**  
在千兆全速下载大文件时，CPU 占用率上升 3% - 5% 属于完全正常的计算消耗。现代电脑处理器的强大算力完全能够轻松驾驭，日常待机时 CPU 占用依然接近于 0%。

### Q3：开启 TUN 模式玩游戏，会被外服游戏的反作弊系统（如 EAC、BattlEye、Vanguard）封号吗？
**答：绝不会！TUN 模式使用的是经过微软 WHQL 数字签名的正规 Wintun 网卡驱动！**  
对于反作弊系统而言，Wintun 仅仅表现为系统的一张正规物理网络适配器，它绝不向游戏客户端的进程内存中注入任何非法动态链接库（DLL），因此绝对不会触发任何第三方内存修改类作弊报警。

### Q4：在 Windows 10/11 上使用便携免安装版（Portable），能不能开启 TUN 模式？
**答：可以开启，但每次启动客户端时必须右键选择「以管理员身份运行」！**  
由于便携版没有在系统中注册常驻特权服务，客户端必须直接拥有管理员权限方可向操作系统动态挂载 Wintun 驱动。想要最省心无感的开机自启体验，强烈推荐使用标准安装版并安装服务模式。

### Q5：为什么在开启 TUN 模式后，电脑原有的本地虚拟机（VMware / VirtualBox）偶尔无法联网？
**答：将虚拟机的网络模式从 NAT 模式修改为「桥接模式（Bridged）」即可完美解决！**  
桥接模式下虚拟机被视为局域网内的独立物理设备，其流量会被宿主机的物理网卡直接分流，避免了双重虚拟 NAT 嵌套引起的路由死锁。

### Q6：TUN 模式和传统的全局代理（Global Mode）到底有什么区别？
**答：这是两个完全不同维度的概念！切勿混淆！**  
- **TUN 模式是“流量捕获手段”**：决定了是只有浏览器走代理，还是整台电脑（含终端、游戏）全部走代理；
- **全局代理是“分流判定策略”**：决定了捕获到的流量是无脑全部发往海外节点，还是智能分流（国内直连、海外代理）。  
**黄金组合是：开启 TUN 模式，同时保持「规则（Rule）」模式！** 既接管了全局所有软件，又保障了国内微信、网银的直连秒开。

### Q7：苹果 M 系列芯片的 MacBook 开启 TUN 模式，待机时耗电会加快吗？
**答：完全不会！Mihomo 内核针对 macOS 的 `utun` 接口进行了深度能效比调优，待机一整晚耗电不到 1%。**

### Q8：开启 TUN 模式后，为什么访问特定国内网站时提示我的 IP 位于境外？
**答：说明您使用的分流规则库过旧，该国内网站的域名未被包含在直连白名单中！**  
在客户端中更新订阅文件，让最新的中国大陆 IP 白名单（`GEOIP,CN`）生效，国内软件即可重新精准识别为本地物理宽带直连。

### Q9：在 Linux 服务器上，无桌面环境下如何确认 TUN 虚拟网卡已经成功启动？
**答：在控制台输入 `ip addr show type tun`：**  
若终端列出了名为 `tun0` 或 `meta` 的网络适配器，且状态显示为 `UP`，即代表 TUN 虚拟网卡已在 Linux 内核中成功就绪。

### Q10：为什么有时候开启 TUN 模式后，在 CMD 执行 `ping` 出来的延迟比右键测速显示的延迟高很多？
**答：因为两者测量的物理目标与协议路径完全不同！**  
右键测速测的是本地到国内中转服务器的单向 HTTP 探针延迟；而终端 `ping google.com` 测量的是通过海外专线穿透到美国 Google 数据中心并返回 ICMP 回包的完整端到端物理时延，真实延迟通常在 100ms - 150ms 之间，完全符合物理常理。

### Q11：在 Windows 上，如何彻底卸载残留的 Wintun 驱动？
**答：通过管理员权限打开 CMD，执行 `pnputil /enum-drivers` 找到 Wintun 的发布名称并执行 `pnputil /delete-driver oemXX.inf /uninstall /force` 强行粉碎清理。**

### Q12：TUN 模式支持在多块物理网卡（例如插着双网线做聚合负载均衡）的电脑上工作吗？
**答：原生支持！Mihomo 会自动绑定跃点数最低的主默认网关。**

### Q13：为什么开启 TUN 模式后，电脑通过浏览器测速（Speedtest）显示的依然是国内电信/联通的 IP？
**答：因为 Speedtest 拥有庞大的全国国内测速节点集群，分流规则精准将其判定为了国内直连（DIRECT）！**  
想要测试海外节点的真实出站极速，请在 Speedtest 页面手动点击「Change Server」，将测速服务器切换至香港、新加坡或洛杉矶的服务器进行测速。

### Q14：开启 TUN 模式后，玩国服腾讯游戏（如英雄联盟、王者荣耀模拟器）会有延迟波动吗？
**答：只要规则模式保持为「Rule」，国服游戏的所有数据包 100% 走本地宽带物理直连，延迟毫秒不差！**

### Q15：苹果 Mac 电脑在安装了特权助手后，换了新的 macOS 升级大版本需要重新授权吗？
**答：苹果每逢发布跨版本大更新（如升级至全新一代 macOS）时，可能会重置系统扩展安全库，届时只需在客户端点击一次重新授权即可。**

### Q16：开启 TUN 模式后，为什么有时候打开电脑设置里的“Windows 更新”会卡在 0%？
**答：因为微软 Windows Update 的部分分发 CDN 节点被部分过度激进的规则集错误判定为了海外代理！**  
在自定义规则最顶部，添加微软官方直连规则：`DOMAIN-SUFFIX,windowsupdate.com,DIRECT` 即可跑满家庭物理宽带极速更新。

### Q17：在移动办公环境下，笔记本合盖休眠后重新打开，TUN 虚拟网卡会自动重连吗？
**答：会自动在 1-2 秒内无感完成内核重载与网关重新对齐！**

### Q18：开启 TUN 模式后，如何针对特定软件（例如迅雷或百度网盘）实现彻底的代理隔离？
**答：利用 Mihomo 的 `PROCESS-NAME` 进程规则实现进程级物理直连：**  
```yaml
prepend-rules:
  - PROCESS-NAME,Thunder.exe,DIRECT
  - PROCESS-NAME,baidunetdisk.exe,DIRECT
```
这些大带宽下载软件产生的所有流量将百分之百被内核放行直连，绝不消耗任何境外代理流量。

### Q19：为什么有时候开启 TUN 模式后，局域网共享文件夹（\\192.168.1.X）打不开了？
**答：因为直连规则中遗漏了私有网段豁免。确保配置中包含了 `IP-CIDR,192.168.0.0/16,DIRECT,no-resolve` 即可一秒自愈。**

### Q20：TUN 模式下的 MTU（最大传输单元）应该配置为多少最合适？
**答：默认推荐保持在 `9000`（开启 Jumbo Frames 巨型帧优化）或标准的 `1500`！**  
Mihomo 内核针对 Wintun 进行了深度优化，自动适配最佳 MTU 尺寸，普通用户完全无需手动篡改该数值。

### Q21：在安卓手机上，CMFA 的 TUN 模式与电脑上的 TUN 模式是一回事吗？

### Q22：开启 TUN 模式后，如何防止 DNS 污染？

### Q23：如果开启 TUN 模式后，偶尔发生网络断流怎么最快排查？

### Q25：苹果 Mac 电脑上的 TUN 模式使用的是哪种底层技术？

### Q36：开启 TUN 模式后，电脑自带的移动热点无法给手机分配 IP 怎么解决？
**答：这是因为 Windows 移动热点的 DHCP 虚拟网关服务与虚拟网卡的 NAT 发生了网段争抢！**  
**一秒化解**：先关闭客户端的 TUN 模式；打开 Windows 移动热点并让手机成功连上；随后在电脑上重新开启 TUN 模式，并在网络连接属性中把 Wintun 的共享目标选为该热点虚拟网卡即可。

### Q37：为什么在 macOS 上使用 TUN 模式时，偶尔会提示“系统扩展已被阻止”？
**答：这是苹果 macOS 内核级安全机制（KEXT / System Extensions）对第三方网络扩展的默认隔离！**  
打开 Mac「系统设置」 -> 「隐私与安全性」 -> 滑动至底部，点击“已阻止系统扩展加载”右侧的「允许」，输入锁屏密码即可永久授权。

### Q38：为什么外服网游联机时，即使开启了 TUN 模式依然偶有丢包跳 ping？
**答：因为您在节点列表中误选了廉价的“公网中转”节点，或者开启了测速自动轮询！**  
公网中转在晚高峰丢包率极高，而自动切线会导致游戏瞬间掉线。必须手动锁定一条采用企业物理双 IEPL 专线的固定节点（如 [光速云](/reviews/guangsuyun)），即可实现全程 0 丢包。

### Q39：在 Linux 无桌面服务器上，如何使用 Systemd 自动化拉起 TUN 模式？
**答：编写标准的 Systemd Service 并在启动前通过脚本自动赋予 Capabilities 特权：**  
```ini
[Unit]
Description=Mihomo TUN Daemon
After=network.target

[Service]
Type=simple
User=root
ExecStart=/usr/local/bin/mihomo -d /etc/mihomo
Restart=always

[Install]
WantedBy=multi-user.target
```
以 root 特权启动服务后，Linux 内核会自动加载 `tun` 模块并挂载虚拟网卡，实现开机完全无人值守加速。

### Q40：开启 TUN 模式后，能否只让特定应用程序走代理，其他程序全部直连？
**答：原生完美支持！使用 Mihomo 内核的 `include-package` 或 `PROCESS-NAME` 白名单机制！**  
在规则最顶部将默认规则反转：声明仅特定进程（如 `git.exe`、`code.exe`、`Telegram.exe`）走节点代理，其他所有未命中规则直接流向 `DIRECT`，实现极简白名单模式。

### Q41：在不同 Wi-Fi 网络（如家用 5G Wi-Fi 与 2.4G Wi-Fi）之间切换时，TUN 驱动会自动重启吗？
**答：会自动在微秒级完成路由表重载而无需物理重启网卡！**  
开启 `auto-detect-interface: true` 后，内核会动态监听操作系统的网络网关变更事件，自动将虚拟网卡的出口对齐新的物理网关。

### Q42：为什么有些杀毒软件在扫描时会提示 Wintun 驱动为“可疑网络过滤驱动”？
**答：因为 Wintun 驱动拥有向操作系统内核注入三层数据包捕获的能力，触发了启发式杀毒引擎的高危行为报警。**  
认准正规官方开源仓库发布的安装包，并在杀毒软件中选择信任该驱动即可。

### Q43：开启 TUN 模式后，BT 种子下载（BitTorrent / qBittorrent）会不会被机场封号？
**答：如果 BT 流量通过代理节点出站，极可能触发海外版权机构投诉导致机场直接封禁账户！**  
**必须做的安全防护**：在规则配置最顶部，将 BT 客户端进程强行设为 DIRECT 直连：
```yaml
prepend-rules:
  - PROCESS-NAME,qbittorrent.exe,DIRECT
  - PROCESS-NAME,Transmission.exe,DIRECT
```
让 BT 流量 100% 走本地宽带物理直连，彻底规避封号风险。

### Q44：在 Windows 10/11 的 WSL2 镜像网络中，如何验证内部 Linux 已经走通 TUN 加速？
**答：在 WSL2 终端中直接执行 `curl -I https://www.google.com`：**  
若瞬间返回 `HTTP/2 200`，且 `traceroute 8.8.8.8` 的第一跳为宿主机的虚拟网关地址，即代表内部子系统已完全享受宿主机 TUN 的硬件级加速。

### Q45：为什么高端出海开发者普遍将 TUN 模式视为生产力工具链的终极标配？
**答：因为 TUN 模式彻底将网络基础设施“隐形化”！**  
它将开发者从繁琐的环境变量配置、端口映射与软件代理排错中彻底解放出来。无论是拉取代码、调试微服务、训练大模型还是编译依赖，整台设备所有网络请求行云流水，让开发者的全部精力专注于创造真正的商业价值！

### Q46：开启 TUN 模式后，电脑原有的 IPv6 流量是如何被接管或拦截的？
**答：Mihomo 内核在虚拟网卡层支持 IPv4/IPv6 双栈协议路由！**  
但为了规避国内运营商劣质 IPv6 路由绕路与严重的 DNS 泄漏问题，客户端默认在 DNS 模块中配置了 `ipv6: false`，并在虚拟网卡层自动将 IPv6 伪造解析静默屏蔽，强制整机流量优雅平稳地回退至抗封锁能力更强的 IPv4 加密专线隧道中传输。

### Q47：在公司内网存在企业专用 VPN（如 Cisco AnyConnect / GlobalProtect）时，TUN 模式如何共存？
**答：利用严格的路由表网段拆解实现“内外双轨并行”：**  
在自定义规则顶部，将公司内网服务器私有网段（例如 `10.0.0.0/8`）强行指定为 DIRECT 直连，并确保公司 VPN 虚拟网卡的跃点数针对内网网段生效；而 TUN 虚拟网卡仅接管 `0.0.0.0/0` 外网出口，实现既能访问公司内部 OA 审批流，又能同时无感加速海外技术文档查询。

### Q48：为什么有些用户在使用 TUN 模式时，测速显示有几百兆带宽，但看 YouTube 依然会自动跳到 480P？
**答：因为测速仅仅测的是单线程峰值吞吐，而 YouTube 视频流播放器高度依赖“持续无抖动的超低丢包率”！**  
廉价公网中转节点在晚高峰丢包率高达 15% 以上，播放器在检测到丢包后会自动触发紧急降码率机制。要彻底锁定 4K 60 帧不降画质，底座必须选用企业物理双 IEPL 专线（如 [光速云](/reviews/guangsuyun)）。

### Q49：TUN 模式下的 UDP 转发缓冲区大小对网络吞吐有何影响？
**答：Mihomo 内核原生优化了系统级 UDP Socket 缓冲区尺寸（默认自动调节至数兆字节）！**  
在高频对战游戏与 Hysteria 2 协议暴力发包时，大容量环形缓冲区能够有效避免突发流量造成的缓冲区溢出（Buffer Overflow）丢包，为竞技游戏提供丝滑稳定的跟手感。

### Q50：开启 TUN 模式后，为什么访问某些国内政企或外卖网站依然能精确识别到我真实所在的城市？
**答：因为这些应用通过调用系统原生的 GPS 硬件接口、Wi-Fi BSSID 热点物理定位或浏览器 HTML5 地理位置 API 获取了物理坐标！**  
TUN 模式接管的是网络 IP 通信层，无法拦截操作系统层面的物理传感器定位权限。若需要隐藏真实地理位置，可以在浏览器或手机权限设置中关闭该网站的“位置信息获取权限”。
