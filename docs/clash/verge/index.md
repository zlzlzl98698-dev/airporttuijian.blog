## 一、直接结论（Answer-First 核心上手闭环法则）

对于想要以最快速度稳定连通出海网络的用户，请遵循以下四大黄金法则：

1. **安装版本首选法则：Windows 用户首推 x64 安装版（Setup），macOS 用户认准 aarch64 芯片架构**：
   Windows 用户优先下载标准安装包（以享受系统服务无缝集成）；macOS 用户若是 M1/M2/M3/M4 系列自研芯片，必须下载 `aarch64.dmg` 版本，彻底告别 Rosetta 2 转译带来的额外电量开销。
2. **极简四步连接工作流**：
   - **安装并中文**：运行安装包，在「Settings」中切换为「简体中文」。
   - **导入订阅**：在「订阅（Profiles）」面板粘贴机场订阅链接点击「导入」，右键配置「自动更新」为 1440 分钟（24 小时）。
   - **选节点并设规则**：在「代理（Proxies）」中保持「规则（Rule）」模式，选中延迟最低的香港或日本节点。
   - **开启系统代理**：在「设置」中将「系统代理」开关拨至开启状态。
3. **驱动级无感出海终极步骤：安装「服务模式」并开启「TUN 模式」**：
   普通的系统代理只能接管浏览器等遵循系统设置的应用。若要让命令行（CMD/PowerShell）、Git 代码拉取、游戏客户端及各类后台程序全部畅通无阻，必须在「设置」中点击「服务模式」右侧的安装按钮（地球图标变绿），随后打开「TUN 模式」，即可实现真正的全局硬件级无感加速。
4. **故障自愈第一原则：遇到全线打不开，先关系统代理、查系统时钟，严禁删除配置文件**：
   90% 的突然断网并非配置损坏，而是本地系统时钟偏差导致 SSL 证书失效、或者旧节点超时导致代理死锁。切勿手抖删除订阅配置，保持冷静按顺序排查即可瞬间复原。

## 二、底层架构剖析：Tauri + Rust 相比传统 Electron 的划时代突破

要理解 Clash Verge Rev 为什么能在极短时间内全面替代 CFW，必须透视其底层工程架构的深刻革新。

```
                  【传统 CFW 架构】 (内存 250MB - 450MB)
  ┌─────────────────────────────────────────────────────────┐
  │ 捆绑完整 Chromium 浏览器核心 + 完整 Node.js 运行时 (臃肿)│
  └────────────────────────────┬────────────────────────────┘
                               ▼ 调用 Go 老版内核 (停更)

                 【现代 Clash Verge Rev 架构】 (内存 50MB - 90MB)
  ┌─────────────────────────────────────────────────────────┐
  │ 前端 UI (React) ──通过 IPC 管道──▶ 后端核心 (Rust / Tauri) │
  │ (直接调用系统原生内置 WebView2 / WebKit，零额外冗余)   │
  └────────────────────────────┬────────────────────────────┘
                               ▼ 深度集成次世代 Mihomo 内核
```

### 1. 内存黑洞的彻底终结：原生 WebView 与 Rust 强强联合
- **旧版 Electron 的致命痛点**：每一个 Electron 软件本质上都是一个披着客户端外衣的完整 Chrome 浏览器。当您开机自启 CFW 时，哪怕只是静默最小化在托盘中，它也必须加载整个渲染进程、GPU 进程与网络进程，空闲常驻内存高达 250MB 至 450MB，并伴随着频繁的垃圾回收（GC）唤醒。
- **Tauri + Rust 的降维打击**：Clash Verge Rev 采用了基于 Rust 语言构建的 Tauri 跨平台框架。在前端展示层，它直接调用 Windows 系统预装的 **WebView2 运行时（基于 Edge 内核）** 或 macOS 系统的 **WebKit 引擎**，完全无需在安装包内携带臃肿的浏览器核心。后端通信与系统服务调度由以高性能、高并发和内存安全著称的 **Rust 语言** 编写，使得客户端在空闲状态下的内存开销**大幅骤降至 50MB - 90MB**，启动速度提升 300%，彻底消除了老旧设备上的卡顿风扇噪音。

### 2. 多进程协同与系统服务隔离模型
Clash Verge Rev 在操作系统中精巧地维护着三个相互协同、权责分明的进程体系：
- **主界面进程（Verge GUI Process）**：以普通用户权限运行，负责提供图形化卡片渲染、用户交互、托盘菜单与快捷键监听。
- **内核守护进程（Mihomo Core Process）**：负责监听本地的混合端口（`mixed-port: 7890`）、建立与外部代理服务器的 TCP/UDP 加密隧道、执行规则分流算法与 Fake-IP 虚拟解析。
- **系统特权服务（Clash Verge Service）**：作为 Windows 独立系统服务或 macOS 守护进程常驻在后台，拥有最高系统管理员特权，专门负责动态安装和拆除 Wintun 虚拟网卡、重写系统内核路由表，确保普通权限的主程序能够安全、平稳地调度驱动级功能。

## 三、全平台保姆级安装与初始化配置完全指引

针对不同的操作系统平台，本站技术组整理了最权威的安全安装指南：

### 1. Windows 平台标准部署流程
- **安装包架构选择**：绝大多数普通的 Intel 或 AMD 64位处理器电脑，下载包含 `x64-setup.exe` 的安装包。追求即插即用或在公司电脑无安装权限的用户，可下载 `portable.zip` 便携免安装版。
- **避坑操作要点**：
  1. 双击运行安装包。如果 Windows Defender SmartScreen 弹出“已保护你的电脑（未知发布者）”蓝色警告框，点击左上方的「**更多信息**」，随后点击右下角弹出的「**仍要运行**」按钮。
  2. 建议安装至默认的 `C:\Program Files\Clash Verge` 路径，避免包含中文或特殊字符的自定义路径导致底层驱动找不到文件。
  3. 启动后，点击左侧侧边栏最下方的「Settings」，找到「Language」下拉框，选择「简体中文」。

### 2. macOS 苹果电脑标准部署流程
- **架构严格对齐**：
  - 苹果 M1/M2/M3/M4 系列芯片电脑：必须下载文件名包含 `aarch64.dmg`（或 `arm64`）的镜像文件。
  - 2020 年之前的 Intel 处理器老款 Mac：下载 `x64.dmg` 镜像文件。
- **签名拦截一秒绕过**：
  1. 双击打开 `.dmg` 镜像文件，将 Clash Verge 图标拖入右侧的 `Applications`（应用程序）文件夹中。
  2. 在访达中首次双击打开时，系统会弹出警告：“无法打开，因为 Apple 无法检查其是否包含恶意软件”。
  3. 点击「取消」，打开 Mac 的「系统设置」 -> 「隐私与安全性」 -> 滑动到底部安全性区域 -> 会看到“已阻止使用 Clash Verge”的提示，点击其右侧的「**仍要打开**」并输入锁屏密码即可永久正常使用。

### 3. Linux 平台（Ubuntu / Debian / Arch）部署流程
- 在 Ubuntu / Debian 桌面系统中，从 GitHub Releases 下载对应的 `.deb` 安装包，在终端中一行指令完成安装：
  ```bash
  sudo dpkg -i clash-verge_1.6.4_amd64.deb
  sudo apt-get install -f # 自动补全依赖
  ```
- 针对 Arch Linux 用户，直接通过 AUR 进行自动化编译构建：
  ```bash
  yay -S clash-verge-rev-bin
  ```

## 四、订阅管理与进阶更新机制深度调优

订阅链接是客户端的灵魂。合理配置订阅拉取机制，能够保证节点库全天候平稳可用：

### 1. 订阅链接的高效导入与命名管理
1. 打开客户端，点击侧边栏的「**订阅（Profiles）**」。
2. 在顶部的输入框中，粘贴从机场后台复制的完整订阅 URL。
3. 点击右侧的「**导入（Import）**」按钮。客户端会自动连接远程服务器下载 YAML 配置文件。
4. 导入成功后，卡片上会显示该配置的名称、更新时间与节点数量。右键点击该卡片选择「重命名」，可以为其设置一个便于识别的名字（例如“光速云主力专线”）。

### 2. 关键参数调优：设置科学的自动更新频次
- **为什么不能设得太短**：很多新手为了追求最新节点，把自动更新时间设为 10 分钟或 1 小时。这不仅毫无必要，还会频繁打断客户端当前的活动连接；更严重的是，可能因高频调用 API 触发服务商防爬防火墙，导致账户被封禁 24 小时。
- **最佳实践**：右键点击订阅卡片选择「编辑」，将「**自动更新间隔（Interval）**」配置为 `1440` 分钟（即正好 24 小时）。这样客户端每天只在后台静默轮询一次，既保证了节点 IP 的微调同步，又完全不占用系统资源。

### 3. 进阶技巧：开启“使用代理更新订阅（Update via Proxy）”
当出现极端网络敏感期、或者服务商的订阅分发域名在国内遭到了运营商暂时的 DNS 污染时，如果直接用本地宽带直连更新必定会提示超时报错。
- **操作步骤**：右键点击该订阅卡片，勾选「**使用代理更新**」开关。
- **实战价值**：勾选后，客户端在刷新订阅时，会强制指定通过当前已经能够正常翻墙的现存代理节点去转发该 HTTP 请求，从海外线路将最新配置抓回本地，轻松破除国内骨干网对订阅域名的封锁。

## 五、服务模式（Service Mode）与 TUN 虚拟网卡深度配置

这是 Clash Verge Rev 区别于普通轻量代理客户端的最核心杀手锏功能。

```
                     【传统系统代理 vs TUN 虚拟网卡模式】
                                       │
         ┌─────────────────────────────┴─────────────────────────────┐
         ▼                                                           ▼
【系统代理 (System Proxy)】                                 【TUN 虚拟网卡模式 (TUN Mode)】
 仅修改注册表 HTTP 钩子                                     安装 Wintun 内核驱动创建物理虚拟网卡
 仅 Chrome / Edge 浏览器主动遵守                            全盘底层接管整台设备 100% 原始数据包
 命令行终端、Git、外服网游全部绕过直连                      终端 git clone、Docker、游戏、UDP 满速加速
```

### 1. 安装服务模式的正确姿势
1. 打开 Clash Verge Rev -> 点击左侧侧边栏「**设置（Settings）**」。
2. 找到「**服务模式（Service Mode）**」配置区域。初次使用时，右侧的小地球图标为灰色，表示服务尚未就绪。
3. 点击右侧的小扳手或安装图标，在 Windows UAC 弹窗中点击「允许（Yes）」。
4. 安装成功后，客户端会自动重启内核服务，此时**服务模式图标会变成高亮的绿色小地球**，代表系统级特权桥梁已搭建完毕。

### 2. 激活 TUN 虚拟网卡模式
1. 在「设置」面板中，找到「**TUN 模式（TUN Mode）**」开关。
2. 将开关拨至高亮开启状态。
3. 打开 Windows 设备管理器，在「网络适配器」列表中可以看到一张名为 `Wintun Userspace Tunnel` 的全新虚拟网卡已经处于启用状态。
4. **即时效果验证**：
   - 打开 Windows 命令提示符（CMD），输入 `ping google.com`，您会惊喜地发现原本不可达的海外域名不仅瞬间解析出 Fake-IP，而且可以顺畅收到 ICMP 回包！
   - 在终端中执行 `git clone https://github.com/...`，下载速度直接拉满千兆物理带宽，再也无需手动配置复杂的代理环境变量。

### 3. TUN 高级网络堆栈选择建议（Stack 选型）
在 TUN 高级配置面板中，提供了三种底层数据包重组网络堆栈（Stack）：
- **gVisor（默认推荐）**：由 Google 开发的用户态网络栈，稳定性和兼容性最为出色，资源占用均衡，适合绝大多数日常开发、办公与网页影音用户。
- **System（系统原生协议栈）**：调用操作系统内核自带的 TCP/IP 堆栈，吞吐性能极高，适合超大带宽下载与本地万兆局域网传输。
- **Mixed（混合模式）**：自动针对不同协议在 gVisor 与 System 之间切换，兼顾两者的长处。

## 六、进阶实战：编写 JavaScript 扩展脚本实现全自动化分流重写与节点清洗

很多服务商下发的默认配置文件中，往往夹杂着诸如“【请加TG群】”、“剩余流量 200G”等无用的广告节点，或者内置的分流规则并不符合您个人的使用偏好（例如您希望 GitHub 走香港节点，而默认配置却走了美国）。

Clash Verge Rev 内置了现代化的 **JavaScript 脚本扩展引擎**，允许您用标准的 ES6 语法，对配置进行动态编程处理：

```javascript
// Clash Verge Rev 生产级自动化配置重构与节点清洗脚本
function main(config) {
  // 1. 全自动过滤垃圾广告节点与公告类伪节点
  if (config.proxies && Array.isArray(config.proxies)) {
    const filterKeywords = ['官网', '返利', '到期', '流量', '通知', '群', '公告', '重置', '测试'];
    config.proxies = config.proxies.filter(proxy => {
      return !filterKeywords.some(keyword => proxy.name.includes(keyword));
    });
  }

  // 2. 注入高强度防 DNS 泄漏与 Fake-IP 最佳实践配置
  config.dns = {
    enable: true,
    listen: '0.0.0.0:1053',
    'enhanced-mode': 'fake-ip',
    'fake-ip-range': '198.18.0.1/16',
    'default-nameserver': ['223.5.5.5', '119.29.29.29'],
    nameserver: [
      'https://dns.alidns.com/dns-query',
      'https://doh.pub/dns-query'
    ],
    fallback: [
      'https://1.1.1.1/dns-query',
      'https://8.8.8.8/dns-query'
    ],
    'fake-ip-filter': [
      '*.lan',
      '*.local',
      'router.asus.com',
      '*.msftconnecttest.com',
      '*.msftncsi.com'
    ]
  };

  // 3. 在最顶部优先注入自定义的业务分流强规则
  const priorityRules = [
    'DOMAIN-SUFFIX,openai.com,🚀 节点选择',
    'DOMAIN-SUFFIX,claude.ai,🚀 节点选择',
    'DOMAIN-SUFFIX,github.com,🚀 节点选择',
    'DOMAIN-KEYWORD,jetbrains,🚀 节点选择',
    'GEOIP,CN,DIRECT'
  ];

  if (config.rules && Array.isArray(config.rules)) {
    config.rules = [...priorityRules, ...config.rules];
  } else {
    config.rules = priorityRules;
  }

  // 返回重构后的完美配置对象
  return config;
}
```

**实操生效路径**：
在「订阅」界面右键点击卡片 -> 选择「编辑脚本」 -> 粘贴上述代码并保存。随后点击一次更新订阅，您的节点列表中所有的广告伪节点将被瞬间清理得干干净净，且所有的安全 DNS 与优先级规则将全自动永久驻留生效！

## 七、Merge 合并配置模式 vs Script 扩展脚本模式深度实战

除了编写 JavaScript 代码的 Script 模式外，Clash Verge Rev 还提供了一种对代码初学者更为友好的**Merge（合并配置）模式**。

### 1. Merge 模式与 Script 模式的技术差异
- **Script 模式（函数式深度编程）**：基于标准的 JavaScript 函数输入输出。功能最为自由强大，支持使用正则循环遍历、动态修改任意属性，适合极客玩家。
- **Merge 模式（声明式纯 YAML 覆盖）**：完全使用标准的 YAML 语言编写，其底层原理是利用深度合并（Deep Merge）算法，将您手写的 YAML 片段直接覆盖并入服务商的原始配置中，无需懂任何 JavaScript 编程语法。

### 2. 生产级 Merge 合并配置模板
在「订阅」界面右键点击卡片 -> 选择「编辑配置（Edit Merge）」 -> 粘贴以下代码：

```yaml
# Clash Verge Rev 纯声明式 Merge 合并增强模板
prepend-rules:
  # 优先强制直连国内高频软件
  - DOMAIN-SUFFIX,bilibili.com,DIRECT
  - DOMAIN-SUFFIX,163.com,DIRECT
  - DOMAIN-SUFFIX,qq.com,DIRECT
  - GEOIP,CN,DIRECT

# 覆写内核 DNS 设置
dns:
  enable: true
  enhanced-mode: fake-ip
  fake-ip-range: 198.18.0.1/16
  nameserver:
    - 223.5.5.5
    - 119.29.29.29
  fallback:
    - https://1.1.1.1/dns-query
    - https://8.8.8.8/dns-query
```

`prepend-rules` 语法会自动将您指定的自定义规则强制插入到服务商规则列表的最顶部，确保其拥有最高的匹配优先级。

## 八、连接监控（Connections）与日志调试（Logs）排障实战

当遇到特定网页打不开或网络卡顿不可思议时，盲目重启软件毫无意义。学会查看 Clash Verge Rev 的底层调试面板，是成为网络高手的必修课：

### 1. 深度剖析「连接（Connections）」控制看板
点击左侧侧边栏的「**连接（Connections）**」图标，可以看到当前整台电脑所有正在进行的网络会话全景图：
- **目标地址与域名（Host / IP）**：清晰展示当前会话真正连接的目标主机。如果发现有大量的后台进程在向境外未知 IP 频繁发送数据，可直接定位流氓后台应用。
- **匹配规则（Rule）**：显示该连接命中了哪一条分流规则（例如 `DOMAIN-SUFFIX,google.com -> 🚀 节点选择`）。如果发现国内网站被分流到了海外节点，观察此列即可精准找到是哪一条规则发生了误判。
- **链路吞吐与耗时（Traffic & Time）**：显示该连接累计消耗的上行与下行流量。点击右上角的「关闭所有连接（Close All）」按钮，可以强制中断当前的全部网络会话，在切换节点后强制所有软件立即使用全新节点重新建立连接。

### 2. 利用「日志（Logs）」面板定位致命故障
点击侧边栏的「**日志（Logs）**」，将日志级别设置为 `info` 或 `debug`：
- **`[DNS] resolve ... failed`**：说明本地 DNS 模块发生了死锁，或者上游 DoH 解析服务器无法连通，提示您需要检查 DNS 配置。
- **`connect error: ... connection refused`**：说明节点服务器的端口被防火墙切断，提示您需要立即手动切换节点。
- **`[TUN] adapter start error`**：说明 Wintun 虚拟网卡驱动被杀毒软件拦截，需要重新安装服务模式。

## 十、长效运维与系统级故障排查 SOP 五步法（SOP Checklist）

无论是在 Windows 还是 macOS 环境下，当遇到网络连接异常时，切勿盲目重复安装卸载。技术组总结了一套标准化的五步长效自检操作清单：

### 第一步：检查系统时钟精度与 NTP 状态（定位 SSL 握手超时）
- **故障表象**：订阅显示正常，但所有节点测速均显示 `Timeout`，浏览器打开任何 HTTPS 网页均提示证书不可信或握手失败。
- **排障操作**：
  1. 在 Windows 任务栏右键点击时钟 -> 选择「调整日期和时间」。
  2. 确认时区设置为正确的本地时区（如中国标准时间 UTC+8）。
  3. 点击「立即同步」按钮，确保与系统网络时间服务器（`time.windows.com`）的时间误差绝对控制在 30 秒以内。由于现代加密协议（如 TLS 1.3、Shadowsocks、VLESS）均依赖时间戳防重放攻击，时钟哪怕偏离 90 秒，也会直接导致全盘握手失败。

### 第二步：网络适配器与 Wintun 驱动状态检测（排查 TUN 虚拟网卡状态）
- **故障表象**：开启 TUN 模式后电脑无法打开网页，或者提示无法绑定驱动接口。
- **排障操作**：
  1. 按下快捷键 `Win + X` 打开设备管理器，展开「网络适配器」分类。
  2. 观察是否存在带有黄色感叹号的 `Wintun Userspace Tunnel` 适配器。
  3. 若存在黄色警告，右键选择「卸载设备」；在 Clash Verge Rev 中关闭并重新开启 TUN 模式开关，客户端会自动重新向操作系统注册一个纯净的 Wintun 驱动实例。

### 第三步：Windows 注册表系统代理端口检查与强行复位
- **故障表象**：关闭 Clash Verge Rev 后，全电脑浏览器彻底瘫痪，无法打开任何国内和海外网页。
- **排障操作**：
  1. 按下 `Win + R` 键输入 `regedit` 回车打开注册表编辑器。
  2. 导航至核心键值路径：`HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Internet Settings`。
  3. 检查键值 `ProxyEnable` 是否为 `0`；若为 `1`，将其强行修改为 `0`；同时将 `ProxyServer` 字符串清空。
  4. 或者在 Clash Verge Rev 的「设置」中，将「系统代理」开关重复快速点击两次（先开后关），客户端会自动向系统触发一次标准的取消代理调用。

### 第四步：端口占用分析与杀毒软件安全例外排除
- **故障表象**：客户端启动报错“Port 7890 in use”或内核异常闪退。
- **排障操作**：
  1. 以管理员身份打开 CMD 或 PowerShell，输入以下指令定位占用 7890 端口的具体进程 PID：
     ```powershell
     netstat -ano | findstr :7890
     ```
  2. 根据输出最后一列的 PID，在任务管理器中找到对应程序。常见冲突源包括老旧的 Clash for Windows、v2rayN 残留进程或其他网络抓包软件。
  3. 在 Windows Defender、火绒或 360 安全卫士中，将 Clash Verge Rev 安装目录（`C:\Program Files\Clash Verge\`）与数据目录（`%AppData%\io.github.clash-verge-rev.clash-verge-rev\`）完整加入杀毒软件的信任白名单，防止误杀内核驱动。

### 第五步：DNS 缓存清洗与 Fake-IP 映射池清空 SOP
- **故障表象**：切换了订阅或更换了直连规则后，特定海外网站依然顽固地连接超时。
- **排障操作**：
  1. 打开终端（CMD），输入以下命令强行刷空操作系统本地的 DNS 解析缓存：
     ```cmd
     ipconfig /flushdns
     ```
  2. 在 Clash Verge Rev 的「连接（Connections）」面板中，点击右上角的「关闭所有连接」按钮，彻底释放之前保留的 Fake-IP 映射表与长连接会话，强制浏览器以新节点的身份重新发起 TCP 三次握手。

## 十一、Clash Verge Rev 深度 FAQ 与高频疑难自愈（30 问 30 答）

### Q1：为什么开启了系统代理后，Edge 浏览器能打开 Google，但在 CMD 终端执行 `ping google.com` 却显示请求超时？
**答：这是完全正常的网络隔离表现！因为普通的“系统代理”只管 HTTP 应用层，ICMP Ping 协议根本不走代理！**  
浏览器的 HTTP/HTTPS 网页请求能够被注册表代理钩子捕获并转发；而命令提示符中的 `ping` 命令发送的是底层的 ICMP 协议数据包，它不属于 HTTP 范畴，会直接通过您的真实物理网卡裸发往公网，自然会被防火墙阻断。**要想在终端中顺利 ping 通海外域名，必须在 Clash Verge Rev 中开启「TUN 虚拟网卡模式」！**

### Q2：安装「服务模式（Service Mode）」时，点击安装按钮一直转圈或报错“Install Failed”该如何彻底解决？
**答：这通常是因为本地第三方安全管家（如 360、腾讯电脑管家、火绒）拦截了服务注册，或者旧服务未彻底卸载。**  
**终极自愈三步法**：
1. 退出电脑上的所有第三方杀毒与安全卫士软件。
2. 以管理员身份打开 Windows PowerShell，执行指令强行删除旧服务残留：
   ```powershell
   sc.exe delete "clash_verge_service"
   ```
3. 重启电脑，再次打开 Clash Verge Rev，以管理员身份运行客户端并重新点击安装服务模式即可顺利绿灯通过。

### Q3：为什么有时候打开软件，提示“启动内核失败，Port 7890 In Use”？
**答：因为上一次关闭软件时，底层的 Mihomo 内核进程发生假死未彻底退出，导致端口被自己强行霸占！**  
**一秒自愈方法**：
- 按下键盘快捷键 `Ctrl + Shift + Esc` 打开任务管理器，在进程列表中找到名为 `clash-verge.exe` 或 `mihomo.exe` 的残留进程，右键点击「结束任务」后重新打开软件；
- 或者在「设置」中将「混合端口（Mixed Port）」由默认的 `7890` 随意修改为 `7897` 或 `10808` 等冷门端口保存即可。

### Q4：在 Windows 上卸载 Clash Verge Rev 后，全电脑网页彻底瘫痪无法上网，怎么在 30 秒内恢复？
**答：这是因为卸载程序没有自动重置系统代理注册表钩子，操作系统依然固执地向不存在的 7890 端口转发数据！**  
**30 秒瞬间复活**：
1. 按下快捷键 `Win + i` 打开系统设置。
2. 依次点击「网络和 Internet」 -> 「代理」。
3. 在「手动设置代理」下方，找到「使用代理服务器」开关，**手动将其拨至“关”**。
4. 随后点击保存，重新打开浏览器即可立刻恢复物理宽带上网。

### Q5：为什么有些节点在测速时显示只有 20ms，但看 YouTube 4K 视频却依然卡顿缓冲？
**答：因为右键测速测得的只是本地电脑到国内中转服务器的单向延迟，完全掩盖了晚高峰极高的网络丢包率！**  
节点的实际体验由“端到端全链路稳定性”决定。如果机场使用的是低成本的公网中转，在晚高峰即使中转机延迟很低，公网出口高达 20% 的丢包率依然会导致视频播放器急剧降低码率并转圈。要彻底杜绝此类问题，必须搭配采用企业物理双 IEPL 专线的优质服务商（如 [光速云](/reviews/guangsuyun)）。

### Q6：在 macOS 上使用 Clash Verge Rev，为什么每次开机都会弹窗要求输入管理员密码？
**答：这是因为开启了 TUN 模式但未将核心授权为系统特权守护进程（Daemon）。**  
在 macOS 版本的「设置」中，找到「安装特权助手（Privileged Helper）」选项并点击安装，在弹出的系统对话框中输入一次 Mac 开机密码完成授权。授权成功后，软件每次开机自启接管虚拟网卡时，将处于静默无感状态，不再弹出任何繁琐的密码确认框。

### Q7：Clash Verge Rev 的配置文件保存在电脑的哪一个具体路径下？我想手动备份该怎么办？
**答：所有核心配置文件、订阅数据库与脚本均持久化保存在操作系统的应用数据专用目录中：**  
- **Windows 系统**：`C:\Users\您的用户名\AppData\Roaming\io.github.clash-verge-rev.clash-verge-rev\`
- **macOS 系统**：`~/Library/Application Support/io.github.clash-verge-rev.clash-verge-rev/`
- **Linux 系统**：`~/.config/clash-verge/`  
直接将该文件夹完整打包压缩，即可在更换电脑或重装系统后，一秒完整还原您的所有订阅历史与个性化分流规则。

### Q8：为什么开启 Clash Verge 后，访问国内的微信、网银 App 或小红书经常提示“网络异常”或频繁掉线？
**答：100% 是因为您将客户端的主模式误设为了「全局（Global）」，或者使用的分流规则库严重过旧！**  
**立即检查**：点击侧边栏的「代理（Proxies）」，查看顶部选中的模式。必须坚决保持为「**规则（Rule）**」！同时在侧边栏「订阅」中，更新订阅文件，确保最新的中国大陆 IP 白名单（GEOIP: CN）处于生效状态，让国内软件坚决走 DIRECT 裸直连。

### Q9：在 TUN 模式下，如何针对特定的外服竞技游戏（如 Apex、CS2、瓦罗兰特）实现超低延迟加速？
**答：在节点列表中手动锁定香港或日本的 IEPL 物理专线节点，并确保节点支持 Full Cone NAT 与 UDP 转发！**  
游戏联机对战走的是基于 UDP 协议的高频实时双向通信。在选择节点时，切勿使用自动测速轮询策略组，必须手动选中一条固定的、具备企业专线保障的低延迟节点，防止在游戏对局途中由于客户端自动换线导致游戏房间闪退断开。

### Q10：Clash Verge Rev 支持多语言界面吗？如果不小心点错切换成了英文，怎么改回中文？
**答：点击左侧侧边栏倒数第二项齿轮图标（Settings），在右侧设置列表中找到第三行「Language」，在下拉菜单中选中「简体中文」即可立刻生效。**

### Q11：为什么在开启代理后，访问某些海外大学网站或下载网盘时，频繁弹窗 Google reCAPTCHA 九宫格验证码？
**答：因为您当前连接的节点海外出口 IP，被大量其他用户共用且从事过高频爬虫，被 Cloudflare 标记为了“机房风险代理 IP”。**  
**解决之道**：在客户端的节点列表中，切换到标有「原生住宅（Residential）」或相对冷门的二线小众专线节点，换用干净纯洁的出口 IP 即可彻底消除人机验证弹窗。

### Q12：Clash Verge Rev 支持通过“快捷键”一键开启或关闭代理吗？
**答：支持！在「设置」 -> 「快捷键」中，可以自由为「切换系统代理」绑定全局热键（如 `Ctrl + Shift + S`），无论在任何全屏工作状态下均可盲操。**

### Q13：为什么我在客户端中修改了配置文件的端口号，但保存后重启软件端口又变回了 7890？
**答：因为您修改的是单次拉取的「订阅文件」，而客户端的端口是由全局的「应用设置（Settings）」所统领的！**  
不要在订阅的 YAML 代码里手动改端口，直接在 Clash Verge Rev 的图形界面「设置」面板中，修改「混合端口（Mixed Port）」输入框中的数值，点击保存即可永久全局生效。

### Q14：开启 TUN 模式后，电脑原有的局域网打印机或 NAS 共享突然搜不到了怎么办？
**答：这是因为 TUN 模式在接管全局网络时，误将局域网多播与广播数据包（mDNS/NetBIOS）也抓取进了虚拟网卡！**  
**排障方案**：打开客户端的 DNS 高级设置，在 `fake-ip-filter` 清单中添加局域网保留域名（如 `*.lan`、`*.local`）；同时在直连规则中确保包含了针对本地私有网段（`192.168.0.0/16`、`10.0.0.0/8`）的 `DIRECT` 规则。

### Q15：苹果 M 系列芯片的 MacBook 使用 Clash Verge Rev，息屏待机一晚上耗电多少？会发烫吗？
**答：基于 Rust + Tauri 的架构功耗极低，配合优秀的 Apple Silicon 优化，待机一整晚耗电量通常低于 1%，且机身全程冰凉无感。**

### Q16：Clash Verge Rev 支持配置“暗黑模式（Dark Mode）”自动跟随操作系统吗？
**答：原生完美支持！在「设置」 -> 「主题设置」中，将主题模式选择为「跟随系统（Auto）」即可。**

### Q17：如果我想让同局域网里的 Switch 游戏机或者备用手机也享受翻墙加速，Clash Verge Rev 能做到吗？
**答：可以！开启「允许局域网连接（Allow LAN）」即可充当局域网共享跳板：**  
1. 在 Clash Verge Rev 的「设置」中打开「允许局域网连接」开关。
2. 查看当前电脑的局域网 IP（例如 `192.168.1.150`）。
3. 在 Switch 或其他手机的 Wi-Fi 设置中，将代理模式选为手动，服务器填写 `192.168.1.150`，端口填写 `7890`，其他设备即可免装客户端流畅出海。

### Q23：升级或频繁重启后，如果提示虚拟网卡 Wintun 驱动损坏或残留，如何通过命令行强制深度清理？
**答：通过 Windows 设备管理器或驱动存储库命令行进行强行清除：**  
1. 以管理员权限运行 CMD 终端；
2. 执行以下指令列出所有的系统网卡设备：
   ```cmd
   pnputil /enum-devices /class Net
   ```
3. 找到驱动名称包含 `wintun` 的条目，记录其发布名称（例如 `oem12.inf`）；
4. 执行强行删除命令：
   ```cmd
   pnputil /delete-driver oem12.inf /uninstall /force
   ```
5. 完成后重新启动 Clash Verge Rev 并重新开启 TUN 模式，驱动将以全新干净状态重新编译挂载。

### Q24：当同时导入多个不同机场的订阅时，如何实现节点按机场分组互不干扰，并配置跨机场自动负载均衡？
**答：利用 Merge 增强配置或 Script 脚本为每个订阅建立独立的策略组（Proxy Group）：**  
在自定义脚本中，通过 `filter` 遍历各配置的节点数组，分别聚合成“机场A-自动选择”与“机场B-自动选择”两个独立的 `url-test` 组，并在顶层的主策略组中放入这两个子组。这样既保留了不同机场的独立计费流量追踪，又能在一个客户端界面中实现跨服务商的自动化故障转移冗余。

### Q25：在移动办公或出差时，从家庭 Wi-Fi 切换到公司局域网或手机热点，Clash Verge Rev 会不会出现无法联网？该如何处理？
**答：网络环境切换时，操作系统的默认物理网关发生改变，可能会导致 TUN 虚拟网卡的默认路由跃点数（Metric）竞争异常。**  
**一秒解决之道**：在托盘右键点击 Clash Verge Rev 图标，依次点击「重启内核（Restart Core）」，或者按下快捷键关闭一次 TUN 模式再重新打开。内核会在 1 秒钟之内自动识别并适配全新的物理网卡 IP 与网关路由，瞬间恢复全速出海。

### Q26：开启 TUN 模式后，为什么 WSL2（Windows Subsystem for Linux）虚拟机内的网络会断开？如何正确配置镜像网络？
**答：WSL2 早期采用的是独立 NAT 虚拟交换机架构，与宿主机的 Wintun 驱动存在路由循环冲突。**  
**现代最佳解决方案**：升级至 Windows 11 并在用户主目录（`C:\Users\您的用户名\.wslconfig`）中开启 **镜像网络（Mirrored Mode）**：
```ini
[wsl2]
networkingMode=mirrored
dnsTunneling=true
firewall=true
autoProxy=true
```
保存后在 PowerShell 中执行 `wsl --shutdown` 重启 Linux 子系统。WSL2 将直接完全共享 Windows 宿主机的网络堆栈，自动无缝享受 Clash Verge Rev 的 TUN 加速，无需在 Linux 内部重复配置任何代理环境变量。

```yaml
  - DOMAIN-SUFFIX,steamcontent.com,DIRECT

  - DOMAIN-SUFFIX,epicgames.com,DIRECT
```
使游戏更新大包 100% 跑满本地家庭宽带的最大千兆物理极速。
