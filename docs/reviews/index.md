::: info 核心评测原则与中立性声明
1. **测试基准透明化**：所有测速报告与拓扑验证均注明中国联通、中国电信、中国移动三网接入环境，严格区分晚间高峰期（20:00—23:30）与日常闲时，杜绝单一时段偶然数据。

4. **商业利益回避规范**：所有官网跳转链接均严格遵循国际搜索引擎准则，统一注入 `target="_blank" rel="nofollow sponsored noopener"` 属性，商业赞助行为绝不干预评测技术评分与排名权重。
:::

## 三、专业评测方法论与反作弊技术审计标准

传统测速博主常用的单张 Speedtest 彩色测速图存在巨大的技术欺骗空间。为了建立可验证的行业评测公信力，本站制定了五大反作弊基准审计规范。

### 1. 为什么绝大多数“测速图”不可信？

1. **服务商专属测速服务器（Speedtest 白名单作弊）**：部分不良商家会在内网配置针对 Ookla Speedtest 测速节点的强行走专线规则，或者在境外机房直接部署同机房内网测速服务器。用户测速时显示 1000Mbps 跑满，但一旦访问 YouTube、GitHub 或 OpenAI，流量便立刻切回廉价拥堵的公网直连链路，导致“测速快如闪电，网页卡成死机”。
2. **闲时突发单线程虚假峰值**：在凌晨三点运行测速脚本，网络处于全天最低负载状态，单连接即可拉满千兆下行；但到了晚间 20:30 到 22:30 的全民高峰期，骨干网发生严重丢包（拥塞丢包率可突破 20%），TCP 拥塞控制算法（如 Cubic）会直接将传输窗口削减至冰点。
3. **节点缓存欺骗（Cache Trick）**：部分节点对常见 100MB 测速分块文件做本地内存缓存，测速工具拉取到的实际上是代理服务器本地 RAM 中的假数据，根本没有产生跨国物理通信。

### 2. 本站五维基准测试矩阵

```
      ┌───────────────────────────────────────────────────────────┐
      │               本站五维基准评测模型 (Audit Matrix)         │
      └───────────────────────────────────────────────────────────┘
                                    │
         ┌──────────────┬───────────┴───────────┬──────────────┐
         ▼              ▼                       ▼              ▼
  【物理专线审计】 【晚高峰压力测试】    【IP风控与反欺诈评分】 【协议原生解析度】
   - ICMP 抖动验证   - 连续 4 小时压力测试   - Scamalytics 欺诈分 - Full Cone NAT
   - 跨国路由追踪   - 丢包率标准差监控     - IP2Location 广播属性 - 多路复用 (MUX)
   - 墙内丢包率     - TCP 重传率分析       - Netflix/OpenAI 实测 - 阻断恢复耗时
```

- **指标一：连续多小时晚高峰丢包与抖动（Jitter & Loss Rate）**：
  我们通过在境内多地部署的发包探测机，在每晚 20:00—23:00 持续以 100ms 间隔向落地节点发送探针，统计平均延迟的标准差（抖动）。标准差小于 3ms 判定为优质专线，大于 15ms 判定为严重超售或拥堵公网。
- **指标二：落地 IP 纯净度与欺诈风险评估（Fraud Score & Subnet Diversity）**：
  使用权威数据库 Scamalytics 与 IP2Location 扫描落地 IP：
  - 欺诈分数（Fraud Score）在 0—15 分：极高纯净度，原生住宅广播，无 Cloudflare 频繁人机验证，完美支持 Claude 3.5 Sonnet 与 ChatGPT Plus。
  - 欺诈分数在 50 分以上：属于高风险机房数据中心广播段，极易触发网站封号或阻断。
- **指标三：真实并发流媒体 4K 缓冲区健康度（Buffer Health）**：
  直接在测试机上运行无头浏览器加载 YouTube 4K 60FPS 与 Netflix HDR 影片，实时监控 `Connection Speed`（连接速率）与 `Buffer Health`（缓冲区存活时间是否维持在 30 秒以上），而非单纯查看瞬间下载数字。
- **指标四：NAT 类型与 UDP 穿透能力（Full Cone NAT）**：
  运行 STUN 客户端检测节点的 NAT 行为。Full Cone NAT（完全圆锥型）为最高等级，允许外服电竞联机、Nintendo Switch、PS5 联机加速以及实时语音（Telegram Call / Discord）无障碍直通；Symmetric NAT（对称型）则会导致联机失败。

## 五、现代网络底层传输与代理协议硬核解构

选择机场绝不能仅仅看外壳包装，必须理解底层物理链路与数据封装协议如何直接决定你的上网体验。

### 1. 物理专线与公网架构对比

```
【普通公网直连】
用户客户端 ──────> 局域公网 ──────> 国际出入口局 (GFW审查+丢包) ──────> 海外落地服务器
                                 ▲ 晚高峰严重 QoS 拥堵，丢包率 > 15%

【BGP 单线/双线中转】
用户客户端 ──(加密)──> 国内云中转机房 ──────> 公网出口隧道 ──────> 海外落地服务器
                                    ▲ 虽有中继，但跨境段仍走公网，敏感期仍受干扰

【IEPL / IPLC 物理专线】
用户客户端 ──(加密)──> 国内 BGP 入口 ══════(物理内网专线)══════> 海外落地专线出口 ──> 互联网
                                    ▲ 物理光缆直连，不走公网 GFW，0 丢包，绝对抗封锁
```

- **IEPL（International Ethernet Private Line，国际以太网专用线路）**：
  IEPL 是跨国电信运营商在物理层面上划分出的以太网二层私有通信通道。客户端发送的数据在进入国内专线机房后，被封装进内网通道，通过物理光缆直接穿过国境线到达香港或日本落地机房。整个传输过程**完全脱离中国公共互联网骨干网，不经过任何 GFW 深度包检测网关**。这也是为什么在每年重大会议期间，公网直连节点全军覆没，而光速云等物理 IEPL 机场依然能稳定秒开网页的底层技术原因。
- **IPLC（International Private Leased Circuit，国际物理租用专线）**：
  与 IEPL 类似，均为端到端物理点对点硬连接。不同之处在于 IPLC 属于更底层的 TDM/SDH 物理链路，成本更高、开销更小。但对于终端用户而言，两者在防封锁和晚高峰抗拥堵上的实际体验基本无差异。
- **普通中转 vs 物理专线**：
  许多不良商家将“国内腾讯云/阿里云公网中转”包装成“专线”。这类中转虽然降低了用户本地连接国内机房的延迟，但从国内机房跨过国境到达海外节点时，**依然使用的是普通的公网国际出口**。一旦遇到骨干网国际拥堵，丢包率依然会飙升，切勿被商家的文字游戏欺骗。

### 2. 现代加密协议演进与选型建议

| 协议类型 | 诞生时期 | 加密与握手特征 | 抗 GFW 探测能力 | 服务端 CPU 负载 | 适合客户端与场景 |
| :--- | :---: | :--- | :---: | :---: | :--- |
| **Shadowsocks (SS)** | 2012 | 基于对称加密流密码（AEAD），特征相对对称 | 弱 (公网裸奔极易被识破) | **极低** | 仅推荐在 **IEPL 物理专线内网** 中作为低开销通道传输 |
| **VMess (V2Ray)** | 2015 | 基于时间戳的动态哈希鉴权，数据包头较重 | 中等 | 中等 | 经典协议，兼容性极好，但特征已较明显 |
| **Trojan** | 2017 | 伪装成正规 HTTPS (TLS) 流量，配合合法域名证书 | 强 | 中等 | 伪装性优秀，适合各类客户端，防主动探测能力强 |
| **VLESS (Reality)** | 2023 | 移除传统加密与时间戳负担，直接借用合法境外大厂 SNI 证书 | **极强 (现役防封王牌)** | **极低** | 目前旗舰机场的首选配置，抗审查与握手性能俱佳 |
| **Hysteria 2 / TUIC** | 2023 | 基于魔改 UDP (QUIC) 协议，激进的拥塞控制算法 | 强 (在恶劣网络下极速抢包) | 较高 | 适合**极度恶劣、丢包严重的公网移动宽带**，但在部分地区会被运营商 QoS 限速 UDP |

> [!TIP] 协议选型核心法则
> 只要你购买的是**真正的 IEPL 物理专线**，协议开销越轻越好（例如 VLESS 或 Shadowsocks-2022），因为数据本身在内网物理管道中运行，无需再叠加沉重的多层 TLS 加密套件；而如果你使用的是**公网直连或普通中转**，则必须使用 VLESS-Reality 或 Trojan 来防范 GFW 的主动探测与封锁。

## 七、机场跑路雷达与高危风险防范手册

在过去的数年间，中文网络代理行业发生过数百起服务商捲款跑路的恶意事件。了解跑路前夕的典型征兆，是每一位用户保护自身资金安全的必修课。

### 1. 跑路高危特征的“六大死兆星”

```
【高危跑路信号雷达】
  ❶ 异常大额超低价促销（如“买一年送一年”、“99元三年无限量”）──────> 准备收割最后一波资金跑路
  ❷ 官方 Telegram 交流群突然开启【全员永久禁言】 ─────────────────> 掩盖大面积断网抗议，管理层失联
  ❸ 节点大面积飘红超过 72 小时无人修复，工单回复周期极具拉长 ────────> 运维欠费被上游机房拉断光纤
  ❹ 频繁更换官网域名、要求用户强制更换支付渠道（甚至要求加密货币） ──> 支付通道被上游清退，现金流断裂
  ❺ 核心技术人员在 TG 频道公开发布带有悲观情绪或与同行撕逼的公告 ───> 团队发生内讧或面临现实法律风险
  ❻ 网站突然删除所有【按月支付】选项，仅保留年付与多年付 ─────────> 放弃长线口碑，彻底转为存量收割
```

### 2. 资金安全对冲的三项铁律

1. **坚持「月付对冲原则」**：
   在尚未对一家新机场建立半年以上的信任之前，**坚决不要为了几块钱的折算折扣去一次性年付**。按月支付虽然单价稍高，但将你的最大潜在损失严格锁定在 10 元至 25 元以内。哪怕商家跑路，也不至于伤筋动骨。
2. **「冷热备用双机场」体系**：
   对于严重依赖外网办公与科研的刚需用户，绝不能把所有鸡蛋放在同一个篮子里。建议配置一套**主力专线机场（如光速云主力月付）**，搭配一套**不限时不过期套餐（如光速云斯诺克 147 包）**或廉价平价机场（如大佬云 5.6 元包）作为“冷备份”。一旦主力遇到偶发机房故障，可在 3 秒内无缝切换至备用节点，保证工作业务永不中断。
3. **订阅链接隐私安全防护**：
   你的机场订阅链接（如 `https://domain.com/api/v1/client/subscribe?token=xxxx`）本质上就是你的私人访问密钥。切勿在公共网络、公用代码仓库（GitHub）或不信任的第三方“免费订阅转换网站”粘贴你的原始链接，否则你的流量极易被第三方中间人节点盗刷甚至嗅探。详细防护请查阅：[订阅安全与防盗指南](/resources/risk-intel/subscription-security)。

### Q1：专线机场和传统海外商业 VPN（如 ExpressVPN / NordVPN）相比，到底哪个更好？
**答：在中国大陆的网络环境下，专线机场在速度、延迟和连通率上全面碾压传统海外商业 VPN。**
传统海外 VPN 采用的是标准的 OpenVPN、WireGuard 或 IKEv2 协议，虽然安全性极高，但它们的协议特征在 GFW 眼中极其明显，且服务器 IP 均为公开静态列表，在大陆境内几乎常年处于被封锁阻断状态，经常面临连不上或掉线的窘境。而专线机场通过国内 BGP 节点进入内网物理光纤（IEPL/IPLC），避开了公网审查，延迟通常在 20ms—40ms（传统 VPN 往往高达 200ms+），且更契合国内 Clash 生态的分流规则。只有当你人在海外、需要高度匿名的金融级加密时，传统海外 VPN 才更适用。深入对比请阅读：[传统 VPN 与代理机场深度对比](/vpn/comparison/vpn-vs-airport)。

### Q2：为什么我的专线机场测速只有 100Mbps，但看 4K 视频比别人 1000Mbps 的直连机场还要流畅？
**答：决定流媒体播放体验的核心指标是「持续丢包率」与「延迟抖动」，而不是「瞬时峰值带宽」。**
播放 4K 视频仅需稳定 25Mbps—35Mbps 的连续吞吐量。专线机场由于走内网专线，丢包率几乎为 0，TCP 窗口无需频繁重传收缩，视频缓冲区能迅速拉满并不再波动；而劣质直连机场虽然能瞬间突发到 1000Mbps，但由于公网高丢包，视频播放器在频繁丢包重传时会反复出现缓冲卡顿（转圈圈），因此“峰值大”并不等于“体验好”。

### Q3：什么是节点的「倍率」？为什么有的节点流量扣得特别快？
**答：倍率是机场统计用户流量消耗时的计费乘数。**
例如：标准节点的倍率为 `1.0x`，你下载了 1GB 文件，账户扣除 1GB 流量；但部分高昂的物理专线或稀缺原生 IP 节点可能会标为 `1.5x` 或 `2.0x`，此时下载 1GB 会扣除 1.5GB 或 2GB 流量。相反，部分冷门或大带宽节点可能标为 `0.5x` 或 `0.2x`（打折消耗）。使用前务必在节点列表确认倍率标注，避免流量意外耗尽。

### Q4：为什么连接了节点后，显示延迟只有 30ms，但打开网页却提示无法连接或超时？
**答：这通常是由本地 DNS 泄漏/污染、系统时间偏差或客户端核心崩溃导致的「假连通」。**
节点列表显示的 30ms 仅仅是你的客户端向国内接入点发送 TCP 握手的时间（即测试延迟只测到了国内第一跳，根本没有测试整个链路到境外落地的真实联通性）。请按照以下 SOP 步骤排查：
1. 检查电脑或手机的系统时钟是否精确同步（时间偏差大于 60 秒会导致 VLESS/VMess 握手直接被拒）；
2. 检查客户端是否开启了「Tun 虚拟网卡模式」以避免本地应用不遵守系统代理；
3. 参考本站专著排查手册：[Clash 节点连通但无法联网十大排查步骤](/clash/troubleshooting/dns-leak-fix)。

### Q5：机场服务商能看到我访问的具体网页内容或账号密码吗？
**答：不能看到具体的通信明文，但能看到你访问的域名目标。**
现代互联网 99% 以上的流量均采用了端到端 HTTPS / TLS 加密传输（如访问各大银行、Google、GitHub）。数据在离开你的浏览器前就已经被加密，机场服务器充当的只是加密数据流的搬运管道，无法解密你的密码、聊天记录或信用卡信息。然而，机场的出口审计系统能够记录你的 DNS 查询请求与目标域名（SNI），因此切勿使用机场节点从事违反当地法律法规的危险行为。

### Q6：光速云的「斯诺克 147 永久包」真的不过期吗？商家靠什么盈利？
**答：只要服务商处于正常运营状态，该套餐就没有时间限制。**
斯诺克 147 套餐的逻辑在于：247GB 流量对于重度刷视频的用户而言可能几个月就消耗完毕，但对于仅用于外贸收发邮件、Google 检索或作为突发备用的用户，这笔 147 元预收资金直接转化为服务商的沉淀现金流，同时该类用户实际占用的带宽峰值开销极低。这是一种双赢的商业模式，非常适合将它放置在客户端中作为“永不断网的应急备用底座”。

### Q7：什么是 UDP Full Cone NAT？为什么游戏玩家必须关注？
**答：Full Cone NAT 是一种允许外部网络主机在收到初始数据包后、主动向该映射端口发送数据的 NAT 行为。**
在游戏领域（如任天堂 Switch 联机、PlayStation 联机、Steam P2P 匹配联机），如果节点不支持 Full Cone，NAT 类型会退化为 Strict（严格型）或 Symmetric（对称型），导致无法与任何其他玩家建立直连房间或出现致命的“NAT 错误代码”。选购时请认准具备 Full Cone 标注的品牌。

### Q8：我的机场订阅在特殊时期经常无法更新，怎么解决？
**答：必须在日常备份「节点导出文件」或使用「订阅镜像域名」。**
正规老牌机场通常会在用户后台提供备用的镜像订阅分发地址（如 Cloudflare CDN 托管的短链），或者支持将节点配置直接以剪贴板代码格式本地导入。建议在日常网络通畅时，将关键专线节点以本地静态配置文件的形式保存在本地电脑中，即便订阅 API 服务器遭突发 DNS 污染，本地节点依然能正常发起通信。
